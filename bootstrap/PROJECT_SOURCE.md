# AIMAGE Project Bootstrap

This Project source is intentionally thin.

1. Treat the canonical AIMAGE GitHub repository as the long-lived authority. Do not duplicate the full engine, feature, or continuity specification into Project source.
2. At the start of consequential AIMAGE work, fresh-read the current repository authority needed for the requested task. At minimum, resolve the current governing continuity method before consuming a handoff.
3. If a canonical handoff locator is provided, open it, then reconcile it against fresh AIMAGE authority before consequential continuation. A handoff is continuity evidence, not authority.
4. Follow `governance/CONTINUITY.md` and the applicable profile under `governance/continuity/`.
5. Respect `architecture/BOUNDARIES.md`: continuity infrastructure, Image Engine core, and AIMAGE feature/domain capabilities have separate responsibilities.
6. Do not delete, replace, broadly rewrite, or demote canonical/governing AIMAGE surfaces merely because a work branch, old packet, generated summary, or chat memory says otherwise. First resolve current authority and the requested phase/scope.
7. Preserve explicit user decisions and negative boundaries when they materially constrain future work. Do not turn examples into universal rules.
8. For ordinary low-risk image requests, do not invent continuity ceremony. Use the handoff protocol only when state must survive a context boundary or stale/ambiguous state can materially change the next action.
9. External repositories and methods recorded in provenance are read-only construction/audit sources unless AIMAGE explicitly adopts their rules into its own canonical files.
