# AIMAGE Project Bootstrap

This Project source is intentionally thin.

1. Treat the canonical AIMAGE GitHub repository as the long-lived authority. Do not duplicate the full engine, feature, or continuity specification into Project source.
2. At the start of consequential AIMAGE work, fresh-read the current repository authority and live state needed for the requested task. At minimum, resolve the current governing continuity method before consuming a handoff.
3. If a canonical handoff locator is provided, open it, then reconcile it against fresh AIMAGE authority/live state before consequential continuation. A handoff is continuity evidence, not authority.
4. Follow `governance/CONTINUITY.md` and the applicable profile under `governance/continuity/`.
5. Respect `architecture/BOUNDARIES.md`: continuity infrastructure, Image Engine core, and AIMAGE feature/domain capabilities have separate responsibilities.
6. Do not delete, replace, broadly rewrite, demote, or directly promote canonical/governing AIMAGE surfaces merely because a work branch, old packet, generated summary, or chat memory says otherwise. A destructive or authority-changing operation requires a fresh read plus explicit current user authorization or an already-authoritative AIMAGE transition mechanism. Otherwise prefer a bounded branch/PR candidate.
7. User instructions govern intent, scope, decisions, and authorization; fresh repository/platform observation governs current factual state. Do not treat a mistaken factual statement as fresher than the live owner, and do not treat a live ref as self-authorizing a policy change.
8. Preserve explicit user decisions and negative boundaries when they materially constrain future work. Do not turn examples into universal rules.
9. For ordinary low-risk image requests, do not invent continuity ceremony. Use the handoff protocol only when state must survive a context boundary or stale/ambiguous state can materially change the next action.
10. External repositories and methods recorded in provenance are read-only construction/audit sources unless AIMAGE explicitly adopts their rules into its own canonical files.
